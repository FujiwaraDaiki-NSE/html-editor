# 思考をAgentへ渡す機能の提案（第2巡）計画

作成日: 2026-08-11
前提: [2026-08-11-intent-handoff-features.md](2026-08-11-intent-handoff-features.md) と [docs/intent-handoff-features.html](../docs/intent-handoff-features.html)（第1巡・候補6件）

## 目的

第1巡は「入力マップ」で失われている思考を7行に整理し、候補を6件出した。
このうち **「ここだけは崩したくない」の行だけが、6候補のどれにも割り当てられていない**。
第2巡はこの残りの穴を埋め、あわせて第1巡が扱わなかった思考（否定、差の知覚、関係）を候補として立てる。

評価軸は第1巡と同じ。変換損失の大きさ／既存機能との接続／ユーザーに新しい作法を要求しないこと。

## 進め方

- [x] 第1巡の入力マップと候補6件を突き合わせ、未割り当ての行を特定する
- [x] `shared/context.mjs` の `editorEnvelope` / `contextPromptRules` を読み、追加コストの実際を確認する
- [x] 注釈レイヤー設計 D9（指差し）/ D11（関係）と重複しない形に整える
- [x] 本命1件の操作・Agentへ渡すもの・渡さないもの・永続化方針を決める
- [x] ユーザー向け提案資料をHTMLで作成する
- [x] 内容と表示を確認する

## 成功条件

1. 第1巡の候補と重複しない
2. 本命が `concept.md` 2.1（無条件上書き・承認ゲートを設けない）と矛盾しないと説明できる
3. 追加するデータが `editorEnvelope` への小さな追加で足りることを示す
4. 「印」が成果物の見た目とエクスポートに影響しない置き方を決める
5. 実装順と、減ったかどうかの測り方を示す

## 非スコープ

- 実装

## 結果

- 提案資料: [docs/intent-handoff-round2.html](../docs/intent-handoff-round2.html)
- 本命: **決まり具合を成果物の上に置く（Firm / Draft マーク）**
  - 無印＝現状の挙動。印は `data-weave-mark` 属性として保存し、エクスポートで落とす（`data-weave-id` と同じ扱い）
  - `editorEnvelope` に `marks: { firm: [], draft: [] }` を足し、`contextPromptRules` に2文足すだけで通る
  - システム的な保護ではない。Agentへ渡す意図であり、上書きは止めない（2.1と非衝突）
- 併走候補: 行き止まりの記憶（undoを否定信号として1件だけ渡す）／重ねて比べる（案の同時比較）／関係を引く（D11、測定後）
