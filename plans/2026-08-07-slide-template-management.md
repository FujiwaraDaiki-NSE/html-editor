# テンプレートスライドの管理（要件）

2026-08-07 検討。初稿は「保存したスライドのコピー」を前提に書いていたが、議論の結果**中身を持たない器（枠）の定義**という別物に落ち着いたため全面的に書き直した。旧稿で悩んでいた論点のいくつかは、この転換で消えている（末尾）。

## テンプレートとは何か

**型は、背景と枠と共通の見た目を持ち、中身は持たない。** PowerPointのレイアウトに近い。

```html
<main class="weave-slide theme-… text-slate-50 text-lg">   ← 背景 ＋ 共通定義（継承元）
  <div class="brand">…</div>                                ← 枠（編集対象外）
  <div data-weave-slot="title">…</div>                      ← タイトル
  <div data-weave-slot="content">…</div>                    ← 内容（中は自由に組める）
  <div class="page-number">…</div>                          ← 枠（編集対象外）
</main>
```

3つの要素からなる。

1. **背景**（配色・装飾）
2. **2つのスロット**（タイトル／内容）。内容スロットの中はコンテナを含めて自由。空でもよい
3. **共通定義**（文字サイズ・色など、スライド全体に効く既定値）

スライドは必ずいずれかの型に属し、**型は後から変更できる**。

## 決定事項

### D1. 保存場所はプロジェクト内 `templates/`

`localStorage`（[app/page.tsx:66](app/page.tsx:66)）から移す。「真実は実ファイル」（concept 2.10）に乗り、`slides/` と同じ書き込み経路・検証・gitコミットを再利用できる。agentからも読める。`assets/` の相対パスもそのまま有効。

デッキをまたいだ再利用（`~/.weave/templates/` 等）は保留。

### D2. 背景の選択と統合する

型が背景を持つ以上、背景だけを別に選ぶUIは残さない。インスペクタの `SLIDE BACKGROUND`（[app/page.tsx:1783](app/page.tsx:1783)）は**型の選択に置き換わる**。

concept 2.7 の「背景はスライドごとに選ぶ／表紙用・本文用を使い分ける／編集不可で用意されたものから選ぶ」は、この型の選択そのものとして実現される。2.7 は本項に吸収する。

### D3. スロットは「タイトル」「内容」の2つ固定

型ごとにスロット数が変わると、型を変更したときにどの中身をどのスロットへ入れるか決まらない。**2つ固定なら タイトル→タイトル、内容→内容 で機械的に決まる**。これが型変更を成立させている条件なので、スロットは可変にしない。

内容が不要な型（表紙など）は、内容スロットを空のまま持つ。スロット自体を無くすことはしない。

### D4. 共通定義はCSSの継承で配る

型のルート要素にクラスを置き、子はそれを継承する。型を変えれば文字の見た目も変わる。

そのため**ブロックの既定クラスから色・文字サイズを外す**。今は全ブロックが自前で持っており（`blockTemplates` [app/page.tsx:91](app/page.tsx:91) の `text-6xl` `text-slate-300` など）、このままでは継承が一切効かない。ブロックは構造だけを持ち、見た目は型から降ってくる形にする。

配れるのは継承するプロパティに限られる。継承しないものを継承させると入れ子で累積して破綻するため、これはCSSの仕様で決まっている。

| | プロパティ | 型が配れるか |
|---|---|---|
| Size / Weight / Leading / Color | `font-size` `font-weight` `line-height` `color` | ○ |
| Align | `text-align` | ○ |
| Marker | `list-style-type` | ○ |
| Gap / Padding / Space above | `gap` `padding` `margin-top` | × |
| Justify / Align items | `justify-content` `align-items` | × |
| Measure | `max-width` | × |
| Background / Border / Radius / Shadow | `background-color` `border-*` `border-radius` `box-shadow` | × |
| Fit / Aspect | `object-fit` `aspect-ratio` | × |

背景色は継承しないが、既定が透明なので**親の背景が透けて見える**。型が `<main>` に敷いた背景が全体に見えるのはこの仕組みであって、継承ではない。子に `bg-slate-800` を付ければその箱だけ変わり、`bg-transparent` に戻せばまた透ける。

### D5. 個別指定は継承より優先。インスペクタに「継承」の選択肢を置く

要素にクラスが付いていればそれが勝つ。既定は継承値。

インスペクタは**実効値を読まない**。各グループに `className: ""` の選択肢を足すだけでよい。`readSelection` はクラスが無いとき既に `""` を返す（[app/page.tsx:272](app/page.tsx:272)）ので、未設定のときそれが自動でアクティブになる。`setUtility`（[app/page.tsx:859](app/page.tsx:859)）は `classList.add("")` で例外を投げるためガードを1行足す。

- `getComputedStyle` を読む案は採らない。`1.125rem`→`18px`、色→`rgb(…)` の正規化とレイアウト後の読み取りが必要で、割に合わない
- 引き換えに「継承で何が降ってきているか」はインスペクタに出ない。実物がキャンバスに見えているので許容する
- ラベルは継承するプロパティだけ「継承」、それ以外は「なし」とする。同じ見た目で意味が違うと後で必ず混乱する
- 副次的な効果として、**一度付けた色やサイズを外す手段**が手に入る（現状は `setUtility` が必ずクラスを足すため解除できない）

### D6. タイトルスロットの中身＝スライド名

今はインスペクタの `Title` 欄（`deck.json` に保存、フィルムストリップの名前）とキャンバス上の見出しが無関係で、同じ文字列を2回打つか放置してズレるかのどちらかになっている。タイトルが型の持ち物になるのを機に、これを1つにする。

**真実はタイトルスロットのテキスト。** `deck.json` の `title` はそこから導出される表示用の値とする（concept 2.10「HTMLが単一の真実」に従う）。

- 同期はクライアントだけで行う。読み込み時にHTMLのタイトルスロットから `title` を上書きし、キャンバス編集時は `syncFromDom` から、インスペクタの `Title` 欄編集時はスロットのDOMへ書き戻す
- サーバはこの規約を知らない。agentがHTMLのタイトルを直接書き換えても、次にエディタが読んだ時点で追従する
- 引き換え: タイトルは型が位置を決めるので、自由に動かせず消せない。ツリーには出すがドラッグ・削除の対象外にする
- 空のときフィルムストリップは `Untitled` にフォールバックする

### D7. 型の適用＝枠の差し替え＋スロットの中身の移動

`<main>` のクラスと枠の要素を新しい型のものに差し替え、2つのスロットの中身をそのまま移す。中身は自由領域の中にあるので**引き継ぎのマッピングは不要**。既存の `checkpoint()` に乗せてUndo一発で戻せる。

「新規スライドを作る」と「既存スライドの型を変える」は同じ操作になる。前者は空のスライドに型を当てるだけ。

## 実装上、先に片付ける必要があるもの

### ブラウザ既定値のリセット

生成CSS（[shared/tailwind-slide.mjs:224](shared/tailwind-slide.mjs:224)）には `h1` `p` などのリセットが無く、`h1` はブラウザ既定の `font-size: 2em` `font-weight: bold` `margin: 0.67em 0` が生きている。今は `text-6xl` が上書きしているので見えていないだけ。

D4でブロックから既定クラスを外すと、**継承値ではなくブラウザ既定値になる**。Tailwind の preflight 相当を生成CSSに足す必要がある。

```css
.weave-slide :where(h1, h2, h3, p, ul, ol) { margin: 0; font-size: inherit; font-weight: inherit; }
```

既存デッキの余白がその分変わるため、見た目の確認が要る。

### スロットの印

`data-weave-slot="title" / "content"` を導入する。テンプレート専用の語彙はこれ1つに留める（プレースホルダ変数や差し込み記法は導入しない）。

ブロックの追加先も現在の `.hero` 決め打ち（[app/page.tsx:801](app/page.tsx:801) の `addBlock`）から、内容スロットを見る形に変える。

### 型の装飾をどう持つか（要決定）

背景の絵（`theme-orbit` の円、`theme-grid` の格子）は継承では配れない。現状は生成CSSに3種が直書き（[shared/tailwind-slide.mjs:233](shared/tailwind-slide.mjs:233)）で、`deck.css` は内容が違うと保存が弾かれる（[server/project.mjs:258](server/project.mjs:258)）。

| 案 | 内容 | 型を誰が作れるか |
|---|---|---|
| A | `theme-*` を増やす | コードを書く人だけ |
| B | `templates/<id>.css` を許す | 誰でも。ただし「生成物は read-only」を開ける |
| C | **装飾も inline SVG としてHTMLに書く** | 誰でも。新しい仕組み不要 |

**推奨はC。** `agentInstructions`（[server/project.mjs:23](server/project.mjs:23)）が既に「装飾は inline SVG、`fill="currentColor"`」と定めており、型がただのHTMLファイルで完結する。`theme-orbit` の円も `::before` である必然性はない。

## UI

- **型を選ぶ／変える** — インスペクタの `SLIDE BACKGROUND` を `SLIDE LAYOUT` に置き換える（[app/page.tsx:1783](app/page.tsx:1783)）。現在の型名を表示し、押すと一覧。ここは既に「スライド全体の設定」の置き場所として機能している
- **新規スライド** — フィルムストリップの「＋」から型を選ぶ。既定の型を1つ指定できるとなお良い
- **一覧の見え方** — 実HTMLをそのまま縮小表示する（サムネイル画像は生成しない。concept 2.3と同じ判断）
- **確定前プレビュー** — 候補を選ぶとキャンバスに当てた状態を表示し、Escで戻る／クリックで確定（`checkpoint()` は確定時のみ）。当ててみないと分からない状態が、型変更をためらわせる最大の理由なので

一括適用（複数スライドをまとめて別の型へ）は、フィルムストリップに複数選択の仕組みが無いため後回し。

## この検討で消えた論点

型が「中身を持たない器」になったことで、旧稿の以下は不要になった。

- 既存スライドに当てたときの中身の引き継ぎ方（種別ごとの出現順マッピング等）。中身はスロットの中にあり、スロットは2つ固定で1対1に対応するため
- 適用時にテーマ・アクセントを当てた先へ揃える処理。型が背景を持つので自動的に一致する
- テンプレートの中身をダミーテキストに置換するか。中身を持たないので発生しない
- テンプレートのリネーム・件数上限・同名保存の上書き確認。「スライドを保存して貯める」機能ではなくなったため、必要になるのは型を増やせるようにしてから（未決2）

（関連する既存不具合）ページ番号 `01 / 01` はフラグメント直書きで再採番されない（[app/page.tsx:141](app/page.tsx:141)）。型の枠が持つ要素になるので、本件で扱うのが自然。
