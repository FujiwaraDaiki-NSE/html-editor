# テンプレートスライドの管理機能（要件検討）

## 目的

「一度作った表紙・章扉・比較レイアウトを、次のスライドや次のデッキでそのまま使い回す」を成立させる。
現状は最小実装が存在するが、保存先がブラウザなので資産として扱えていない。

## 現状（すでにあるもの）

`app/page.tsx` に「Slide library」が実装済み。

- `templateStore`（`app/page.tsx:66-82`）— `localStorage` の `weave.slideTemplates` に `SlideDoc[]`（id/title/notes/html）をJSONで保存
- `saveSlideTemplate`（`app/page.tsx:1006`）— 現在のスライドをそのまま保存
- `insertTemplate`（`app/page.tsx:1012`）— 現在位置の次にスライドとして挿入（slide idだけ振り直し）
- UI — キャンバスツールバーの `Save template` / `Library`（`app/page.tsx:1637`）とモーダル一覧（`app/page.tsx:1848`）

### 現状の限界（今回の要件はここから出る）

1. **プロジェクトの外にある**。`localStorage` なのでgit履歴に残らず、agentからも見えず、デッキと一緒に移動しない。2.10で決めた「真実は実ファイル」から外れた唯一の永続データになっている
2. **管理操作がない**。リネーム・削除・並び替えができない。保存はタイトル一致で暗黙上書き（`app/page.tsx:1008`）、31件目で古いものを黙って捨てる
3. **一覧が中身を表さない**。サムネイルは固定の `background-preview orbit` スウォッチで、どのテンプレートも同じ見た目に並ぶ
4. **テーマが混ざる**。背景・アクセントはスライド単位で `<main>` のクラスとして持つ（`setSlideBackground` `app/page.tsx:903`）。別テーマで保存したテンプレートを挿入すると、そのスライドだけ配色が変わる
5. **画像を含むテンプレートが壊れうる**。保存HTMLの `img` は `assets/...` のプロジェクト相対パス（`app/page.tsx:295`）。別プロジェクトへ持ち込むと画像が消える
6. **新規スライドと繋がっていない**。「＋」は常に `blankSlideHtml`（`app/page.tsx:952`）で、テンプレートは別導線

（付随・既存不具合）ページ番号 `01 / 01` はフラグメントに直書きで再採番されない（`app/page.tsx:141`）。テンプレート経由でも複製される。テンプレート機能とは独立の問題として扱う。

## スコープの定義：何を「テンプレート」と呼ぶか

混同しやすい3つを分けておく。今回扱うのは (A) のみ。

| | 内容 | 今回 |
|---|---|---|
| A. スライドテンプレート | スライド1枚まるごとの型（構造＋ダミーテキスト） | **対象** |
| B. 背景／テーマ | 最背面レイヤーと配色（concept 2.7） | 対象外（既存の背景選択） |
| C. ブロック | 見出し・表・metrics等の断片（`blockTemplates`） | 対象外（既存） |

## 要件

### 必須

- R1. テンプレートは**プロジェクト内の実ファイル**として保存し、git履歴に乗る（`localStorage` から移行）
- R2. 現在のスライドをテンプレートとして保存できる。名前を付けられる
- R3. 一覧から選んでスライドとして挿入できる
- R4. テンプレートの**リネーム・削除**ができる
- R5. 同名保存は**明示的な上書き確認**を経る。件数上限に当たったら黙って捨てず、ユーザーに知らせる
- R6. 一覧は**実HTMLを縮小表示**する（サムネイル画像は生成しない。concept 2.3と同じ判断）
- R7. 挿入したスライドは**挿入先デッキの背景・アクセントに揃う**
- R8. 保存・挿入とも既存の保存経路（`writeProject` の検証・content policy・git commit）を通る

### あるとよい

- R9. 「＋」（新規スライド）からテンプレートを選べる。既定テンプレートを1つ指定できる
- R10. テンプレートの並び替え
- R11. agentがテンプレートを読める／作れる（`AGENTS.md` に置き場所を書く）
- R12. 既存テンプレートへの「現在のスライドで更新」

### やらない

- プレースホルダ変数・差し込み記法（テンプレート専用の語彙を増やさない）
- テンプレート単体のバージョン管理・履歴UI（gitがすでに持っている）
- 共有マーケットプレイス、テンプレートの自動レイアウト提案

## 論点と推奨

### 論点1：保存場所 → **決定：プロジェクト内 `templates/`**（2026-08-07）

`templates/<id>.html` ＋ `.weave/deck.json` にメタ。`slides/` と同じ書き込み経路・検証・gitコミットに乗る。
「真実は実ファイル」（2.10）から外れず、agentからも見え、`assets/` の相対パスがそのまま有効。

デッキをまたいだ再利用（`~/.weave/templates/` 等）は保留。concept 2.7で未決の「背景テンプレートはどこから供給されるのか」と同じ問題なので、まとめて決める。

### 論点4：画像アセット

`assets/` は同一プロジェクト内なのでパスがそのまま有効＝**追加対応なし**。デッキ横断（保留した案）を選ぶときだけ、画像の同梱／複製が要る。

## 適用（本題）

現状の「適用」は `insertTemplate`（`app/page.tsx:1012`）だけ＝**テンプレートを新しいスライドとして次の位置に挿す**、の1モード。
実際に必要になるのは「**いま編集しているスライドに型を当てる**」（PowerPointの「レイアウトの変更」に当たる操作）で、そこが手薄。改善はこの4つに分解できる。

### 論点6：適用の単位＝何が置き換わるか

現状はテンプレートが `<main class="weave-slide">` 丸ごと。適用＝スライドまるごとの差し替えになる。

| 案 | 保存するもの | 適用時の挙動 |
|---|---|---|
| a | `<main>` 丸ごと（現状） | 背景・アクセント・ページ番号もテンプレのものになる |
| b | **`.hero` の中身だけ** | 枠（brand / page-number / 背景クラス）は当てた先のものが残る |

**推奨：b。** 3つ効く。

1. **テーマ混在（論点3）が消える**。背景・アクセントは `<main>` のクラスなので、触らなければ当てた先の配色のまま。R7のための特別処理が要らなくなる
2. **「新規に挿す」と「既存に当てる」が同じ1操作になる**。どちらも `.hero` の中身の差し替え。挿入は「空スライドを作って当てる」に還元される
3. ページ番号の直書き（`01 / 01`）をテンプレートが持ち回らない

制約：`.hero` は `blankSlideHtml` とseedが作る構造で、agentが書き換えたスライドには無いことがありうる。無い場合は `<main>` 直下のコンテンツを対象にするフォールバックが要る。

### 論点7：既存スライドに当てたとき、中身をどうするか

論点6のbでも、当てた先に既に書いたテキストがある場合の扱いは別問題。

| 案 | 挙動 | 評価 |
|---|---|---|
| a | 引き継がない（中身は捨てて型で置き換え） | 単純。ただし「書いた後で型を変える」ができないので、適用の価値が半減する |
| b | **種別ごとに出現順で移す** | heading→heading、paragraph→paragraph、image→image。テンプレ側に余ったスロットはダミーのまま。当てた先に余った中身は末尾に残して捨てない |
| c | スロットを明示（`data-weave-slot="title"` 等） | 対応は正確だが、テンプレート専用の語彙が増え、テンプレ作成が2段階作業になる |

**推奨：b。** 種別はすでにクラス（`heading` / `paragraph` / `image`…）が持っているので**新しい語彙が要らない**。「捨てない」ので誤爆しても失うものがなく、Undoは既存の `checkpoint()` 一発で戻る。

### 論点8：確定前に結果が見えること

「当ててみないと分からない」状態が、適用がためらわれる最大の理由。

**推奨：ライブラリで候補を選ぶと、キャンバスに実際に当てた状態をそのまま表示する。** Escで元へ、クリックで確定（`checkpoint()` は確定時のみ）。
実HTMLをそのまま出す方式なので**サムネイル生成が要らない**（concept 2.3で実HTMLのライブ表示を選んだのと同じ判断）。一覧のR6もこれで満たせる。

### 論点9：導線

現状の `Save template` / `Library` はキャンバスツールバー（`app/page.tsx:1637`）にあり、集中表示（focus mode）では消える。

- **当てる**：インスペクタの `SLIDE` / `SLIDE BACKGROUND` の並びに **`SLIDE LAYOUT` 行**を足す（現在の型名を表示し、押すと一覧）。ここはすでに「スライド全体の設定」の置き場所として機能している（`app/page.tsx:1778-1800`）
- **新規に挿す**：フィルムストリップの「＋」から型を選ぶ（既定の型を1つ指定できるとなお良い＝R9）
- **保存する**：現在の `Save template` はキャンバスツールバーに残す（編集中の操作なので）

複数スライドへの一括適用は、フィルムストリップに複数選択の仕組みが無いため後回し。

## 段階

- **P0** — 保存場所を `templates/` へ移す（R1, R8）。テンプレートの単位を `.hero` に決める（論点6）
- **P1** — 適用の改善（論点7・8）と管理操作（R2〜R6）
- **P2** — 新規スライド導線への統合、agent連携（R9〜R12）、一括適用

## 未決

- 「別デッキでも使いたい」が出たときの受け皿（背景テンプレートの供給元＝concept 2.7の未決とセットで決める）
- 既存の `localStorage` テンプレートを移行するか捨てるか
- テンプレート件数の上限を残すか（残すなら上限到達時の挙動）
- `.hero` を持たないスライドに適用したときのフォールバック
