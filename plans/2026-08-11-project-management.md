# スライドのプロジェクト管理 — 要件定義

- 作成日: 2026-08-11
- 状態: 要件定義（実装未着手）
- UIモック: https://claude.ai/code/artifact/63d283f7-cbc3-4410-b7fb-7962ea069ed6
- 関連: [concept.md](../concept.md) 3章「複数ファイルプロジェクトの構成・管理方法」（アイデア段階のまま残っていた項目）

## 1. 背景と目的

現状、編集対象は `workspaces/northstar/` の1つに固定されている。`projectRoot` は
[server/project.mjs:13](../server/project.mjs) のモジュール定数で、環境変数 `WEAVE_PROJECT_ROOT` で
上書きできるだけ。つまり**Weaveは同時に1デッキしか持てず、別のデッキを作る手段が画面上にない**。

目的は、複数のスライドプロジェクトを作り、一覧から選んで開けるようにすること。
データモデルは既に「1プロジェクト＝1ディレクトリ＝1 gitリポジトリ」で完結しているので、
新しい概念は増やさない。**足すのは「複数あること」と「切り替えること」だけ**。

## 2. スコープ

### 対象

| # | 機能 |
|---|---|
| FR-1 | プロジェクト一覧（1枚目のライブHTML縮小つき） |
| FR-2 | 新規作成（テンプレート選択＋名前） |
| FR-3 | 切替 |
| FR-4 | 改名 |
| FR-5 | 複製 |
| FR-6 | アーカイブ |

### 対象外（今回やらない）

| やらないこと | 理由 |
|---|---|
| `workspaces/` 配下以外の任意フォルダを開く | パス検証とサンドボックス範囲（Codexの `writableRoots`）の再設計が要る。置き場所を固定すれば今回は不要 |
| 複数プロジェクトの同時オープン | サービス層をマルチインスタンス化する必要がある。切替で足りる |
| アーカイブ復元のUI | `workspaces/.archive/<slug>` を戻せば一覧に復帰する。UIを持つ価値が出るまで保留 |
| 検索・並び替えの選択 | 最終保存の新しい順で固定する。件数が増えてから |
| プロジェクト間のスライド／テンプレート／CSSの共有 | 複製でまかなう |

## 3. データモデル

### 3.1 プロジェクトの実体

プロジェクトは `workspaces/<slug>/` の1ディレクトリ。中身は**現状のまま変えない**。

```
workspaces/<slug>/
  .weave/deck.json     スライド順・タイトル・ノートのマニフェスト
  slides/<id>.html     真実。<main> フラグメント
  styles/deck.css      生成物
  templates/<id>.html  テンプレート枠
  assets/              画像
  AGENTS.md            agentへの指示
  .git/                履歴と提案ブランチ
```

### 3.2 レジストリを持たない

一覧は `workspaces/` を readdir し、`.weave/deck.json` を持つディレクトリを列挙して作る。
**プロジェクト台帳ファイルは作らない**（実体とレジストリが食い違う状態を作らないため）。
ドット始まりのディレクトリは除外する（`.archive` がここに入る）。

| 項目 | 取得元 |
|---|---|
| 表示名 | `.weave/deck.json` の `title` |
| スライド枚数 | `.weave/deck.json` の `slides.length` |
| 最終保存 | 最新コミットの committer date |
| サムネイル | `slides/<先頭>.html` と `styles/deck.css` の実体 |

### 3.3 slug と表示名

- **slug は作成時に確定し、以後変えない**。改名は `deck.json` の `title` だけを変える
- 理由: ディレクトリ名を動かすとgitリポジトリのパス、Codexスレッドの `cwd`、開いているプロジェクトの記録がまとめて外れる。表示名だけ変えれば足りる
- slug は名前から `[a-z0-9-]` に落として生成。既存と衝突したら `-2`, `-3`
- 名前が空、または slug が空文字になる場合は `deck`, `deck-2`

### 3.4 カレントプロジェクトの記録

サーバーは「いま開いている1つ」だけを持つ。永続化はリポジトリルートの `.weave/current.json`。

- `workspaces/` と混ざらない場所に置く
- `.gitignore` に `/.weave/` を追加する（`/workspaces/` は既にある）
- 記録された slug が存在しない場合は、最終保存が最も新しいプロジェクトへフォールバック
- 環境変数 `WEAVE_PROJECT_ROOT` は**起動時の初期カレントとして維持する**。既存テスト
  （[tests/project-transaction.test.mjs:13](../tests/project-transaction.test.mjs)、
  [tests/project-templates.test.mjs:41](../tests/project-templates.test.mjs)）がこの前提で書かれている

## 4. 機能要件

### FR-1 一覧

トップバー左の `project-switcher`（[app/page.tsx:2003](../app/page.tsx)）を押すと全画面ギャラリーが開く。
現在の `project-menu` ポップオーバーは廃止し、「Import project」はギャラリー内へ移す。

- カードは 16:9 のサムネイル＋表示名＋「N枚 · 最終保存」
- **サムネイルは1枚目のHTMLの実物**。1280×720のまま縮小して描画する。PNG等の生成物は持たない
- プロジェクトごとに `deck.css` が異なりうるので、カードは `iframe` で隔離する
- 現在開いているプロジェクトはアクセント枠と「開いています」で示す
- 並びは最終保存の新しい順
- Esc または × で閉じ、元の編集状態に戻る

**受け入れ条件**: `workspaces/` に3件ある状態でギャラリーを開くと3件が並び、各カードに実際の1枚目が表示される。1件のCSSを変えても他のカードの見た目は変わらない。

### FR-2 新規作成

ギャラリー先頭の「＋ 新規プロジェクト」から、同じオーバーレイ内で1段深い画面へ。

- Orbit / Grid / Plain を**実際の枠のHTMLで**3枚並べて選ばせる（`builtInTemplates`）
- 名前を入力する。入力に追従して `workspaces/<slug>` を表示する
- 作成すると `mkdir` → 既存の `ensureProject()` 相当（deck.css・templates・AGENTS.md・表紙1枚）→ `git init` → 初回コミット
- 作成後は**そのまま新しいプロジェクトが開く**

**受け入れ条件**: 作成直後にギャラリーを開き直すと新しいカードが先頭にあり、選んだテンプレートの表紙が映っている。作成したディレクトリは独立したgitリポジトリで、コミットが1つある。

### FR-3 切替

カードを押すとそのプロジェクトへ切り替わる。詳細は5章。

### FR-4 改名

カードの `⋯` メニューから。`deck.json` の `title` を書き換えて保存（＝コミット）する。
開いているプロジェクトはトップバーの `document-title`（[app/page.tsx:2009](../app/page.tsx)）でも従来どおり改名できる。

**受け入れ条件**: 改名してもディレクトリ名は変わらず、gitの履歴と開いているスレッドが維持される。

### FR-5 複製

カードの `⋯` メニューから。

- `.git` を除いた中身をコピーし、新しい slug で `git init` ＋初回コミット
- **git履歴は引き継がない**（提案ブランチ・detached状態を巻き込まないため）
- 表示名は「<元の名前> のコピー」
- 複製直後は開かない（一覧に留まる）

**受け入れ条件**: 複製後、元のプロジェクトの履歴・提案ブランチは影響を受けない。複製先はコミット1つの新規リポジトリになっている。

### FR-6 アーカイブ

カードの `⋯` メニューから。確認のうえ `workspaces/.archive/<slug>/` へ移動する。

- **実削除はしない**。gitごと残るので、ディレクトリを戻せば一覧に復帰する
- 開いているプロジェクトはアーカイブできない（先に切り替える）
- アーカイブの結果0件になった場合はギャラリーの空状態を表示する

**受け入れ条件**: アーカイブ後に一覧から消え、`workspaces/.archive/<slug>/.git` が残っている。

## 5. 切替の要件（この機能の中核）

サーバーは**単一カレント方式**を取る。`projectRoot` をモジュール定数から
「現在のプロジェクトを保持する状態」に変え、切替時に差し替える。

### 5.1 切替の手順

1. 切替可能か検査する（5.2）
2. 未保存なら保存（＝コミット）する
3. 実行中のturnがあれば中断し、Codexクライアントを停止する
4. カレントを差し替え、新しいプロジェクトへ `ensureProject()` を通す
5. Codexクライアントを新しい `cwd` で起動し直す
6. SSEへ `project-changed` を流し、クライアントは新しいプロジェクトで初期化する

Codexのスレッドは `cwd` で絞り込まれている（[server/codex/service.mjs:178](../server/codex/service.mjs)、
[server/codex/service.mjs:212](../server/codex/service.mjs)）ため、**会話履歴はプロジェクトごとに自然に分かれる**。
切替時に前のプロジェクトの会話は見えなくなり、戻れば再び見える。

### 5.2 切り替えられない・条件つきの状態

| 状態 | 扱い |
|---|---|
| 未保存の変更がある | 確認ダイアログ。「保存して切替」か「キャンセル」の2択。**破棄して切替は用意しない**（Undo履歴ごと失う操作を切替のついでに起こさないため） |
| 履歴閲覧中（detached HEAD） | 確認なしで `main` へ戻してから切り替える（既存の `checkoutMain()`） |
| **未決着の提案ブランチがある** | **切替不可**。カード上に理由と次の一手（採用／history送り／破棄）を出す |
| agentが実行中 | 確認のうえturnを中断してから切り替える |

未決着の提案で切替を止めるのは、「ブランチは必ずマージ／history送り／破棄のいずれかで閉じる」という
既存の不変条件（concept.md 2.3）を、切替が黙って破らないようにするため。

### 5.3 切替中の表示

Codexの起動し直しに1〜2秒かかる。押したカードにローディングを出し、完了と同時にエディタが
新しいプロジェクトで立ち上がる。失敗した場合は元のプロジェクトに留まり、理由をギャラリー上に出す。

## 7. API

すべてローカルAPI（[server/local-api.mjs](../server/local-api.mjs)）に追加する。

| メソッド / パス | 内容 |
|---|---|
| `GET /api/projects` | 一覧。`[{ slug, title, slideCount, updatedAt, current, blocked }]` とサムネイル用の1枚目HTML・CSS |
| `POST /api/projects` | 新規作成。`{ title, template }` → 作成して開く |
| `POST /api/projects/current` | 切替。`{ slug, save }` |
| `PATCH /api/projects/:slug` | 改名。`{ title }` |
| `POST /api/projects/:slug/duplicate` | 複製 |
| `POST /api/projects/:slug/archive` | アーカイブ |

サムネイルのHTMLは一覧応答に含める（プロジェクト数は数十を想定し、追加のラウンドトリップより単純さを取る）。

## 8. 非機能・制約

- **パス検証**: slug は `[a-z0-9-]+` のみ受け付ける。`..` や絶対パスは受理しない。すべての操作は `workspaces/` 配下に閉じる
- **監視**: [vite.config.ts:8](../vite.config.ts) の `**/workspaces/northstar/**` を `**/workspaces/**` に広げる。`.archive` は除外する
- **移行**: 既存の `workspaces/northstar` はそのまま1件目として列挙される。移行処理は不要
- **初回起動**: プロジェクトが0件のときは、従来どおり既定のプロジェクトを自動生成して開く（`ensureProject()` の挙動を変えない）。アーカイブで0件になった場合のみ空状態のギャラリーを見せる
- **README**: 「編集対象は `workspaces/northstar/` に自動作成されます」の記述を更新する

## 9. この文書で置いた前提

未確認のまま決めた点。違えば差し戻す。

1. **初回起動は既定プロジェクトを自動作成**（空ギャラリーから必ず作らせる方式は採らない）
2. **並びは最終保存の新しい順で固定、検索なし**
3. **アーカイブの復元はUIを持たない**（ファイルを戻す）

## 11. 完了の確認

- 3件のプロジェクトを作り、一覧・切替・改名・複製・アーカイブがひと通り動く
- 切替後、agentが**新しいプロジェクトのファイルだけ**を読み書きする
- 切替後、チャットスレッドが切り替わり、戻ると元の会話が見える
- 未保存・履歴閲覧中・未決着の提案の3状態で、5.2の通りに振る舞う
- `npm run lint` と `npm test` が緑（既存テストは `WEAVE_PROJECT_ROOT` 前提のまま通ること）
