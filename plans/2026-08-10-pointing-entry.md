# 指差しの入口を `@` へ移す 実装計画

作成日: 2026-08-10
設計: [docs/annotation-layer-design.md](../docs/annotation-layer-design.md) D1 / D6 / D9（R2 / R4 / R5 / R6 改訂）
前提: 注釈レイヤー P0–P3 が `feat/annotation-layer` に入っている

## 何を変えるか

1. **ラベルは矩形だけのもの**にする。要素の注釈からラベルUIを外す（D1）
2. **要素の指差しを通常の編集モードへ出す**。入口は入力欄の `@`（D9）
3. **注釈モードは矩形専用**にする。モード中のキャンバスは完全に不活性（D6）

データの形・送信契約・チップ・添付・重ね照合は変えない。`label` は空文字のまま要素の注釈にも残る（スキーマ不変）。

---

## P6: ラベルを矩形専用にする

- `AnnotationOverlay`: `target.kind === "element"` のときラベル入力を描かない。番号は出す
- 要素の注釈は移動・リサイズを持たない（`refreshAnnotations` が実要素の矩形で毎回上書きするので、動かしても意味がない）。残すのは削除だけ（R6）
- `AnnotationLegend` は現状のまま（要素は種別＋抜粋、矩形はラベルを出している）
- `annotationEnvelope` は `label` を送り続ける。要素では常に空文字

**受け入れ条件**

- 要素の注釈にラベル欄・リサイズハンドルが出ない
- 矩形の描き味（作成直後のラベルフォーカス）が変わらない

---

## P7: `@` の入口と指し待ち

**状態**: `pointerPicking: boolean`。通常モードでのみ真になりうる。

**armする**

- `<textarea>`（`app/page.tsx:1984`）で `@` が入力されたら arm する。**IME合成中は発火しない**（`compositionRef` と `nativeEvent.isComposing`）
- 打たれた `@` は本文に残る。確定時に挿入するのは番号だけ（`2`）で、結果が `@2` になる
- `mode === "preview"` かつ `annotationMode` が偽のときだけ arm する

**指し待ちの見え方**（D9）

- `.slide-viewport` に `data-pointer-picking="true"`。CSS はビューポート内側のリング。**スライドの中身は暗くしない**
- 注釈オーバーレイに候補レイヤーを描く。矩形は `liveAnnotationBoxes()` の結果をそのまま使う
  - DOM順（親→子）で描くので、子が親の上に重なり、内側優先の当たり判定が自然に出る
  - 枠はヘアライン、ホバー中の1つだけ実線
  - 各枠の左上にタブ。文言は `elementKind · textExcerpt`（抜粋は短く切る）。既に指した要素は `@N` を出す
  - タブは枠の上辺の**外側**に出す。`y` が上端に寄っている枠は内側へ寄せて画面外に出さない
  - タブを押すとその枠の要素、内側を押すと最も内側の要素
- `.canvas-interaction-status`（`app/page.tsx:2034`）に `picking` 状態を足す。文言は「参照する要素をクリック · Esc でキャンセル」

**確定する**

- 既存の要素注釈作成ロジック（現 `onCanvasPointerEnd` の element 分岐）を関数に切り出して共用する
- 同じ要素を再び指したら増やさず、既存の注釈を選ぶ
- 参照は**キャレット位置**へ挿入する。挿入後は入力欄へフォーカスを戻し、キャレットを挿入直後へ置く
- 確定したら disarm する

**抜ける**

- Esc、枠のない場所のクリック、注釈モードへの切替、Code ビューへの切替、スライド切替

**純関数は `shared/annotation.mjs` へ**

- `insertReferenceAt(text, caret, order, { hasAtSign })` → `{ text, caret }`
- タブ文言の整形（抜粋の切り詰め）

**受け入れ条件**

- `tests/annotation.test.mjs` に挿入関数のテスト（`@` 直後・文中・末尾・本文が空）
- 指し待ち中に本体のDOMが一切変化しない（ドラッグ並べ替え・contenteditable が起きない）
- ズーム 25% / 100% / 400% で枠がスライドに追従する
- 日本語入力で「＠」やローマ字変換中の `@` によって arm しない

---

## P8: 選択から教える

- 要素を選択している間、`.canvas-interaction-status` に押せる `@` を出す（文言に `@` を含める。例: `@ で参照`）
- 押すと選択中の要素で確定する（指し待ちを経由しない）。本文が空でなければ空白を挟んで `@N` を足す
- 押せるのは通常モード・`agentReady` のときだけ

**受け入れ条件**

- キーを知らなくてもボタンだけで参照を作れる
- ボタン経由とキー経由で同じ注釈・同じ本文になる

---

## P9: 注釈モードを矩形専用にする

- `onCanvasPointerDown` の注釈モード分岐から要素選択（`readSelection` / `setSelectedId`）と `elementId` を外す。ドラッグしなかったクリックは何も作らない
- インスペクタの注意書き（`app/page.tsx:2180`）を「モード中は矩形だけ」に直す
- ステータス文言を「注釈モード · ドラッグで矩形を描く」に直す
- ショートカット一覧（`app/page.tsx:1820`）に `@` を足す
- README の該当箇所を直す
- `npm run lint` / `npm test` を緑にする

---

## P10: 実物を見て決めた調整

P7–P9 を実デッキで触って決めた4点。設計の変更ではなく、密度の実測に対する手当てである。

- **タブは常設しない。** 1枚に候補が17個あり、タブを全部出すと互いに重なって本文を隠した。タブが要るのは**枠の内側を押せない要素**——子候補に覆われた入れ子の親——だけなので、常設は「他の候補を含む要素」と「すでに指した要素（`@N`）」に限り、葉要素はホバー中だけ出す（D9の逃げ道として書いてあったもの）
- **タブは支援技術に出さない。** 枠とタブが同じ要素を2回ボタンとして露出していた。操作の本体は枠なので、タブは `aria-hidden` かつフォーカス不可にする
- **抜粋は `<br>` を空白として読む。** `textContent` では「Stories come alivethe moment…」になる。`innerText` は候補ごとにレイアウトを走らせるので使わず、純関数として `editable-text-utils` に置いてテストする
- ステータス行の `@ Reference` に左右の余白

## 触らないもの

- 送信契約（`canSendTurn`・`requireText`・steer）
- チップの矩形トグルと参照によるON戻し
- 添付・下書きへの復元・重ね照合（P4は未着手のまま）
- コンポーザの contenteditable 化（D7 のとおり行わない）
