# Weave

人間とAgentが同じスライドを共同編集する、HTMLネイティブなAIプレゼンテーション制作ツールです。一般的なWebサイト制作やJavaScript開発ではなく、16:9のデッキ、発表者ノート、プレゼン、書き出しまでを一つの制作環境で扱います。

チャットから「新しいプロジェクトを作って」「分割表示にして」など、やりたいことを依頼できます。Agentは現在の画面を確認し、人間と同じボタンや入力欄を操作します。操作前に対象の枠とポインターが表示されるため、操作場所も確認できます。サイドバーは常設で、チャット・デザインなどの内容を切り替えて使います。

画面操作を担当するチャットと、スライドのファイル編集を担当する処理を分けています。スライド編集には従来の変更範囲・実行方法・プレビュー・復元処理を使用します。プロジェクトを切り替えても会話を継続できます。ファイル選択、認証、印刷、全画面などブラウザー自身の操作が必要な箇所は、人間が操作します。

## スライド制作スキル

標準スキルの共通基準と、技術報告の判断・作成者の好みを分けています。既存環境の更新では、アプリを停止して専用の移行コマンドを実行してください。保存先の指定、独自編集の扱い、学習履歴の保持は[開発者向けの整理・移行サマリー](docs/slide-skill-consolidation-summary.html)を参照してください。

## 起動

Node.js 22.13以降と、利用する接続先のCLI（Codex CLIまたはClaude Code）が必要です。

```bash
npm install
npm run dev
```

起動スクリプトが3444番から空きポートを選び、Viteをそのポートで起動します。3444番ポートが使用中の場合は、次の空きポート（3445など）が選ばれます。既定ではこのPCからだけ接続できます。

同じLANの別PCから接続する場合は、公開してよいLANインターフェースのIPv4アドレスとポートを明示して起動します。`0.0.0.0` のような全インターフェース指定は使用できません。

```bash
WEAVE_WEB_HOST=172.30.128.50 WEAVE_WEB_PORT=3444 npm run dev
```

外部PCでは `http://172.30.128.50:3444`、起動したPCでは `http://localhost:3444` を開きます。LANインターフェースを指定した場合も、この2つのアドレスだけで待ち受けます。ローカルAPIは別ポートへ公開せず、Vite経由で利用します。

`npm run dev`は画面、ローカルAPI、Codex app-serverをまとめて起動します。OpenAIの資格情報をアプリ内へコピーせず、Codex CLIの既存ログインを利用します。

### Claude Codeを使う

editorを起動するホストの同じユーザーで、Claude Codeにログインしてください。動作確認済みのバージョンは2.1.322です。`--restricted`と`--permission-prompts`に対応したCLIが必要です。

```bash
claude auth login
claude auth status
npm run dev
```

Agent入力欄のモデルメニューで **Claude Opus 5.5 / Claude Sonnet 5.5 / Claude Haiku 5.5** などバージョン付きのモデル を選びます。初回はモデルを明示的に選択してください。Claude選択時は `editor → ローカルAPI → claude -p → Claude` の経路で実行し、Codex app-serverを経由しません。会話にはCodexの接続は不要です。スライドの実装担当にはCodexの接続と明示的なモデル選択が必要です。バージョン付きの選択では `claude-opus-5-5` などの正式なモデルIDをそのままClaude Codeへ渡します。Opusは5.5 / 5 / 4.8 / 4.7 / 4.6、Sonnetは5.5 / 5 / 4.6、Haikuは5.5を掲載しています。「最新版」と表示する従来のエイリアスも残します。バージョン指定時にCLIが異なるモデルを選んだ場合は失敗として扱い、別モデルへの自動フォールバックは行いません。実際のモデル利用権限はClaude Codeのアカウントに従います。

Claude Codeの既存ログインをそのまま使うため、editorへのAPIキー入力は不要です。接続失敗時は「設定 → Claude Code → 接続を再確認」で再確認できます。認証状態は接続確認時点の値で、実行時の認証期限切れなどはその依頼の失敗として表示します。

ClaudeはオーケストレータとしてRead / Glob / Grepとeditor専用のMCPツールを利用します。ファイルの直接編集とシェル実行は提供しません。MCP接続はeditorが用意するものだけに限定し、実行中の会話・ターンに結び付いた一時トークンを使います。スライドの実装はCodexへ委任し、Claudeが変更前後の内容をレビューした後に反映します。既存の編集範囲検証・プレビュー・変更レビュー・同時編集の保全処理は共通です。

会話の続きはClaude CodeのセッションIDを指定して再開します。editor用の会話履歴はリポジトリの `.weave/claude/` にプロジェクト別に保存し、Git管理の対象にしません。Claude Code自体のセッション保存先はCLIの通常設定に従います。実行中にeditorが終了した依頼は成功として扱わず、自動再送もしません。

オーケストレータのモデルを切り替えると、新しい会話を開始します。会話履歴は接続先ごとに保持します。実行中も追加指示を送れます。Claudeでは現在の応答だけを中断して同じ会話を再開し、Codex担当の作業は維持します。会話分岐、内部ゴール、editorからの手動圧縮操作はClaudeでは未対応です。実装担当のコマンド承認には選択中のCodex承認設定を使います。

### Dockerで常駐起動（Linux）

既存の依存関係、保存データ、ログイン済みCodex CLIを利用します。`npm install` 済みのこのリポジトリで、`.env` に次の値を明示してください（すべて必須）。

```dotenv
WEAVE_UID=1000
WEAVE_GID=1000
WEAVE_REPO_ROOT=/absolute/path/to/html-editor
WEAVE_HOST_HOME=/home/your-user
WEAVE_NODE_ROOT=/absolute/path/to/node-installation
```

`WEAVE_UID` / `WEAVE_GID` はホストユーザーのID、`WEAVE_NODE_ROOT` は `bin/node` と `bin/codex` を含むNode.jsインストール先です。リポジトリ、`WEAVE_HOST_HOME/.codex`、`WEAVE_HOST_HOME/.local/state/weave` をコンテナに共有するため、保存データ、Codexの認証・状態、Agent実行前の復旧スナップショットはホストに残ります。

`WEAVE_HOST_HOME` 全体は読み取り専用で共有します。上記のリポジトリ、`.codex`、復旧データは個別の書き込み可能なマウントです。ホームの共有自体ではコピーや全ファイルの走査を行いません。

初回起動前に、`WEAVE_HOST_HOME` のユーザーで復旧データ用ディレクトリを作成してください（以下のパスは `.env` の `WEAVE_HOST_HOME` に合わせます）。このディレクトリは `WEAVE_UID` / `WEAVE_GID` で書き込める必要があります。未作成の場合は、root所有のディレクトリが自動作成されないようComposeの起動をエラーにします。

```bash
mkdir -p /home/your-user/.local/state/weave
```

```bash
# Linux/AppArmor host: install the dedicated profile before creating the container.
sudo install -m 0644 docker/weave-codex.apparmor /etc/apparmor.d/weave-codex
sudo apparmor_parser -r /etc/apparmor.d/weave-codex
docker compose up -d --build
docker compose logs --tail=100 web
docker compose stop
```

画面は `http://127.0.0.1:3444`、ローカルAPIは `127.0.0.1:4317` を使います。Linuxのhostネットワークで起動します。再起動ポリシーは `unless-stopped` です。Docker起動時やプロセス異常終了時に自動起動し、明示的に停止した場合は停止状態を維持します。

DockerでもClaudeを使う場合は、ホストでログインを済ませ、`.env` に `WEAVE_CLAUDE_BIN` としてネイティブ版Claude Code実行ファイルの絶対パスを指定してください。`command -v claude` で確認できます。npmのJavaScriptランチャーではなく、Linux用ネイティブ実行ファイルを使います。`.claude/` と `.claude.json` がホストに存在する必要があります。次の追加設定で実行ファイルと既存ログイン・セッションをコンテナへ共有します。

```bash
docker compose -f compose.yaml -f compose.claude.yaml up -d --build
docker compose -f compose.yaml -f compose.claude.yaml exec web claude auth status
```

CLIを更新した場合はコンテナを再作成して共有先の実行ファイルを更新してください。

## オーケストレータと実装担当

入力欄のモデルメニューがオーケストレータの選択を兼ねます。Claude／Codexのどちらでも、実装は別のCodex担当へ委任します。「実装担当（Codex）」でモデルと推論レベルを選んでください。未選択時に別モデルへ自動で切り替えることはありません。

実行方法は次の2種類です。編集権限は常に付与し、着手前の承認待ちは設けません。

- **編集をまかせる**：1案を実装し、オーケストレータのレビュー後にそのまま反映します。速度を優先する場合に使います。
- **3案から選ぶ**：対象スライドごとに3案を実際に作成し、レビュー済み候補を表示します。ユーザーが採用するまで編集中の資料は変更しません。

3案は共通の元データから独立した保存先で作成し、デッキ全体では同じ3方向を各ページで維持します。作成開始時から、各スライドのキャンバス上部に高さ36pxの帯を重ね、「編集中｜A｜B｜C」の切り替えタブと「比較」「履歴」を表示します。案名は選択中タブだけに表示し、長い場合は省略、狭い幅では非表示にします。状態の点はレビュー済みが緑、その他がmuted色で、タイトルと状態はホバーでも確認できます。作成中の案も開いて進捗と安定したプレビューを確認でき、レビュー完了後に採用できます。未採用の案はチャットが流れた後も、再読み込み・サーバー再起動後もそのスライドから開けます。単独の案を選んでも上部の帯とスライドの位置・大きさを保ち、スライド直下の浮いたバーから説明の表示・採用・終了を操作できます。「案を比較」で実物を並べて見られます。

案を開いてチャットすると、その案だけに修正を依頼できます。入力欄に修正対象を明示し、入力中に別の案へ切り替えて対象が変わることを防ぎます。「このスライドに採用」で1枚ずつ反映し、スライドごとに異なる案を選べます。残りの未採用スライドは引き続き選択可能です。「提案を終了」は候補を削除せず比較履歴へ送ります。採用後も比較履歴から案を見返せます。

候補作成後に資料を編集した場合は更新表示を出し、採用時に3方向マージで照合します。同じ箇所に競合があると採用を拒否して既存の編集を保持します。閲覧・比較操作では編集中の資料やGitブランチを切り替えません。新しい比較候補はプロジェクトの `.weave/slide-proposals.json`、独立した生成先は `workspaces/.proposals/` に保存します。

どちらのモードでも、相談や計画の依頼には会話で回答します。作業中も追加指示を送れ、オーケストレータが担当の継続・変更・停止を判断します。3案は別々のCodexサブエージェントで最大3案を並列生成します。各案のタブの点とホバー表示、選択中タブの短い状態文言で作成・レビュー状態を示し、レビューが完了した案から、ほかの案を待たずに開いて比較・採用できます。同じ案への修正と通常編集は競合しないように順序を制御し、その間も会話を続けられます。受付・担当状態は `.weave/orchestration.json` に保存し、再起動時の未完了作業を自動再実行・再送しません。

3案の要件と確認項目は [agent向け実装記録](docs/slide-proposals.md)、開発者向け概要は [3案比較の実装概要](docs/slide-proposals-summary.html) を参照してください。

開発者向け概要は [オーケストレーションの実装概要](docs/agent-orchestration-summary.html)、agent向け要件と確認項目は [要件・実装記録](docs/agent-orchestration.md) を参照してください。

## 現在触れる機能

- アウトラインからスライドを切り替える
- スライド表示領域とプレゼン画面で、下スクロールで次、上スクロールで前のページへ移動する（連続したスクロールは1ページ分。入力欄や拡大中のスクロール領域は通常どおり操作）
- 複数スライドを個別のHTMLファイルとして編集・追加する
- プレビュー内の要素を選び、インスペクタのテキスト編集と同期する
- オブジェクトツリーから要素を選択・削除する
- 要素をドラッグしてフロー内の順番を変える
- Heading、Body、Metrics、Footnoteブロックを追加する
- ビジュアル編集、分割表示、検証付きHTML直接編集を切り替える
- Agentへ指示を送り、応答と作業状況をストリーミング表示する
- Agentが選択要素と実プロジェクトを読んで編集する
- チャット欄の `@` または選択中の参照ボタンで要素を指し、ラフモードのドラッグで矩形だけを描いて、デッキへ保存せずAgentに送る
- 送信済みの注釈を下書きへ戻したり、現在の結果へ重ねて意図とのずれを見比べる
- 複数の探索案をAgentが生成し、通常編集を続けながら比較・部分採用する
- 選んだ案を採用し、未採用案を保留またはアーカイブする
- スライド背景とアクセントカラーを変更する
- ダーク／ライトモードを切り替える
- 作業中ドラフトを自動保存し、節目だけ名前付きマイルストーンとして残す
- 履歴から過去の状態を新しいドラフトとして開く
- ビジュアル編集とHTML編集の選択位置、レイヤー、インスペクターを同期する
- Row、Column、Gridコンテナを含む入れ子ブロックを編集する
- インスペクタで文字サイズ、太さ、配置、色、余白、Grid列数を変更する
- スライドを複製・削除・並べ替え・改名し、個人ライブラリへテンプレート保存する
- 編集操作をUndo/Redoし、キーボードだけでも直接編集する
- 25–400%ズーム、実寸、画面に合わせる表示を切り替える
- 品質チェックでエラー・警告・提案を区別し、対象要素へ移動する
- 発表者モードでスピーカーノートを見ながら発表する
- 全スライドを単一のオフラインHTMLプレゼンとして書き出す
- version付き`.weave.json`バンドルでデッキとCSSを安全に持ち運ぶ
- リビジョン競合を検知し、デッキと生成HTMLをトランザクション保存する

編集対象のプロジェクトは `workspaces/<slug>/` に自動作成されます。`.weave/deck.json` が作業中ドラフト、`slides/` 以下のHTMLが各スライドの内部表現です。Gitはマイルストーンと安全な復旧を支える内部実装で、通常の制作操作にGit知識は不要です。

Codex app-serverとの通信は公式のJSON-RPCライフサイクル（初期化、thread、turn、通知ストリーム）に沿ってローカルAPIが担当します。ブラウザからapp-serverや資格情報へ直接アクセスしません。

生成済みapp-server型のCLI版と実行中CLI版が異なっても、起動時には警告メタデータとして保持し、`initialize` → `initialized` のハンドシェイクが成功する限り利用を続けます。実際の初期化に失敗した場合だけ、画面に再生成・確認手順付きの `incompatible` 状態を表示します。型の差分を確認するだけなら、既存ファイルを変更せず、差分がある場合は比較用の一時生成物を残す `npm run codex:check` を使ってください。意図的に更新するときだけ `npm run codex:generate` を実行します。

## 検証

```bash
npm run lint
npm test
```

キーボード操作は画面左のキーボードボタンまたは `?` で一覧できます。主な操作は左右キーでスライド移動、Enter/F2で直接編集、チャット欄の `@` で要素を参照、`A` でラフモード、Escapeで取消、Cmd/Ctrl+ZでUndoです。

`npm test` はプロダクションビルドと、レンダリング結果・主要機能の構成確認を行います。

要件と設計判断は [concept.md](./concept.md) にまとまっています。

チャットによる画面操作の責務と確認方法は [開発者向けサマリー](./docs/chat-operated-ui-summary.html) を参照してください。

参照資料の「＋ ホームのフォルダーを登録」から、Dockerホストのホーム配下を選択できます。パスだけを登録するため、容量・ファイル数の登録上限はありません。Agentは登録済みの実パスから必要な資料を読み取り、元ファイルの更新もそのまま参照します。登録を解除しても元フォルダーは削除しません。隠しフォルダーとホーム内を参照するリンクも選択できます。

別のPCのフォルダーは「PCのフォルダーをアップロード」から選択します。この操作ではサブフォルダーを保持してコピーするため、最大2,000ファイル・合計500 MBの転送上限があり、隠しファイルは対象外です。過去にコピーしたサーバーフォルダーの更新機能も維持しています。

### html-editor共通スキル

「スキル」画面で、全資料に共通する制作指示を作成・編集・アップロードし、有効・無効を切り替えられます。有効な指示は次のAgent依頼から参照されます。資料ごとの適用範囲や格上げ・格下げ操作はありません。

保存先はhtml-editorの `.weave/skills/` です。`WEAVE_SKILLS_ROOT` を指定すると保存先を変更できます。Codex共通の `$CODEX_HOME/skills/` は変更しません。旧スキルのファイルは保持されます。再利用するものは「SKILL.mdをアップロード」から登録してください。

開発者向けの仕様は [html-editor共通スキルのsummary](docs/editor-shared-skills-summary.html) を参照してください。

Agentは修正のやり取りから再利用できる指示を見つけると、「今回の指示を、ほかの資料にも活かしますか？」と提案します。元の指示・適用理由・保存する全文を確認し、「全資料の共通スキルに保存」を選ぶと新規作成または既存スキルの更新を行います。「今回は保存しない」を選んでも資料の修正は保持されます。未回答の提案は再読み込み後もスキル画面から確認できます。既存スキルが提案後に変更されていた場合は上書きを拒否します。

資料制作の知見をまとめた共通スキルの配布原稿は [slide-authoring](skills/slide-authoring/SKILL.md) です。内容の意味・情報の関係・図表と実画面・統一感・画像・事実の扱い・表示確認を扱います。[出典と適用範囲](skills/slide-authoring/references/sources.md)、[開発者向けsummary](docs/slide-authoring-skill-summary.html) を参照してください。別環境へ導入する場合は「SKILL.mdをアップロード」で登録できます。GUIで編集する実体と配布原稿は自動同期しません。
