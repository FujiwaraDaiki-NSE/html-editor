# Weave

人間とAgentが同じスライドを共同編集する、HTMLネイティブなAIプレゼンテーション制作ツールです。一般的なWebサイト制作やJavaScript開発ではなく、16:9のデッキ、発表者ノート、プレゼン、書き出しまでを一つの制作環境で扱います。

## 起動

Node.js 22.13以降と、ログイン済みのCodex CLIが必要です。

```bash
npm install
npm run dev
```

起動スクリプトが3444番から空きポートを選び、Viteをそのポートで起動します。3444番ポートが使用中の場合は、次の空きポート（3445など）が選ばれます。既定ではこのPCからだけ接続できます。

同じLANの別PCから接続する場合は、公開してよいLANインターフェースのIPv4アドレスとポートを明示して起動します。`0.0.0.0` のような全インターフェース指定は使用できません。

```bash
WEAVE_WEB_HOST=172.30.128.50 WEAVE_WEB_PORT=3444 npm run dev
```

外部PCでは `http://172.30.128.50:3444`、起動したPCでは `http://localhost:3444` を開きます。LANインターフェースを指定した場合も、この2つのアドレスだけで待ち受けます。ローカルAPIは別ポートへ公開せず、Vite経由で利用します。

`npm run dev`は画面、ローカルAPI、Codex app-serverをまとめて起動します。OpenAIの資格情報をアプリ内へコピーせず、Codex CLIの既存ログインを利用します。

### Dockerで常駐起動（Linux）

既存の依存関係、保存データ、ログイン済みCodex CLIを利用します。`npm install` 済みのこのリポジトリで、`.env` に次の値を明示してください（すべて必須）。

```dotenv
WEAVE_UID=1000
WEAVE_GID=1000
WEAVE_REPO_ROOT=/absolute/path/to/html-editor
WEAVE_HOST_HOME=/home/your-user
WEAVE_NODE_ROOT=/absolute/path/to/node-installation
```

`WEAVE_UID` / `WEAVE_GID` はホストユーザーのID、`WEAVE_NODE_ROOT` は `bin/node` と `bin/codex` を含むNode.jsインストール先です。リポジトリ、`WEAVE_HOST_HOME/.codex`、`WEAVE_HOST_HOME/.local/state/weave` をコンテナに共有するため、保存データ、Codexの認証・状態、Agent実行前の復旧スナップショットはホストに残ります。

`WEAVE_HOST_HOME` 全体は読み取り専用で共有します。上記のリポジトリ、`.codex`、復旧データは個別の書き込み可能なマウントです。ホームの共有自体ではコピーや全ファイルの走査を行いません。

初回起動前に、`WEAVE_HOST_HOME` のユーザーで復旧データ用ディレクトリを作成してください（以下のパスは `.env` の `WEAVE_HOST_HOME` に合わせます）。このディレクトリは `WEAVE_UID` / `WEAVE_GID` で書き込める必要があります。未作成の場合は、root所有のディレクトリが自動作成されないようComposeの起動をエラーにします。

```bash
mkdir -p /home/your-user/.local/state/weave
```

```bash
docker compose up -d --build
docker compose logs --tail=100 web
docker compose stop
```

画面は `http://127.0.0.1:3444`、ローカルAPIは `127.0.0.1:4317` を使います。Linuxのhostネットワークで起動します。再起動ポリシーは `unless-stopped` です。Docker起動時やプロセス異常終了時に自動起動し、明示的に停止した場合は停止状態を維持します。

## 現在触れる機能

- アウトラインからスライドを切り替える
- スライド表示領域とプレゼン画面で、下スクロールで次、上スクロールで前のページへ移動する（連続したスクロールは1ページ分。入力欄や拡大中のスクロール領域は通常どおり操作）
- 複数スライドを個別のHTMLファイルとして編集・追加する
- プレビュー内の要素を選び、インスペクタのテキスト編集と同期する
- オブジェクトツリーから要素を選択・削除する
- 要素をドラッグしてフロー内の順番を変える
- Heading、Body、Metrics、Footnoteブロックを追加する
- ビジュアル編集、分割表示、検証付きHTML直接編集を切り替える
- Agentへ指示を送り、応答と作業状況をストリーミング表示する
- Agentが選択要素と実プロジェクトを読んで編集する
- チャット欄の `@` または選択中の参照ボタンで要素を指し、ラフモードのドラッグで矩形だけを描いて、デッキへ保存せずAgentに送る
- 送信済みの注釈を下書きへ戻したり、現在の結果へ重ねて意図とのずれを見比べる
- 複数の探索案をAgentが生成し、通常編集を続けながら比較・部分採用する
- 選んだ案を採用し、未採用案を保留またはアーカイブする
- スライド背景とアクセントカラーを変更する
- ダーク／ライトモードを切り替える
- 作業中ドラフトを自動保存し、節目だけ名前付きマイルストーンとして残す
- 履歴から過去の状態を新しいドラフトとして開く
- ビジュアル編集とHTML編集の選択位置、レイヤー、インスペクターを同期する
- Row、Column、Gridコンテナを含む入れ子ブロックを編集する
- インスペクタで文字サイズ、太さ、配置、色、余白、Grid列数を変更する
- スライドを複製・削除・並べ替え・改名し、個人ライブラリへテンプレート保存する
- 編集操作をUndo/Redoし、キーボードだけでも直接編集する
- 25–400%ズーム、実寸、画面に合わせる表示を切り替える
- 品質チェックでエラー・警告・提案を区別し、対象要素へ移動する
- 発表者モードでスピーカーノートを見ながら発表する
- 全スライドを単一のオフラインHTMLプレゼンとして書き出す
- version付き`.weave.json`バンドルでデッキとCSSを安全に持ち運ぶ
- リビジョン競合を検知し、デッキと生成HTMLをトランザクション保存する

編集対象のプロジェクトは `workspaces/<slug>/` に自動作成されます。`.weave/deck.json` が作業中ドラフト、`slides/` 以下のHTMLが各スライドの内部表現です。Gitはマイルストーンと安全な復旧を支える内部実装で、通常の制作操作にGit知識は不要です。

Codex app-serverとの通信は公式のJSON-RPCライフサイクル（初期化、thread、turn、通知ストリーム）に沿ってローカルAPIが担当します。ブラウザからapp-serverや資格情報へ直接アクセスしません。

生成済みapp-server型のCLI版と実行中CLI版が異なっても、起動時には警告メタデータとして保持し、`initialize` → `initialized` のハンドシェイクが成功する限り利用を続けます。実際の初期化に失敗した場合だけ、画面に再生成・確認手順付きの `incompatible` 状態を表示します。型の差分を確認するだけなら、既存ファイルを変更せず、差分がある場合は比較用の一時生成物を残す `npm run codex:check` を使ってください。意図的に更新するときだけ `npm run codex:generate` を実行します。

## 検証

```bash
npm run lint
npm test
```

キーボード操作は画面左のキーボードボタンまたは `?` で一覧できます。主な操作は左右キーでスライド移動、Enter/F2で直接編集、チャット欄の `@` で要素を参照、`A` でラフモード、Escapeで取消、Cmd/Ctrl+ZでUndoです。

`npm test` はプロダクションビルドと、レンダリング結果・主要機能の構成確認を行います。

要件と設計判断は [concept.md](./concept.md) にまとまっています。

参照資料の「＋ ホームのフォルダーを登録」から、Dockerホストのホーム配下を選択できます。パスだけを登録するため、容量・ファイル数の登録上限はありません。Agentは登録済みの実パスから必要な資料を読み取り、元ファイルの更新もそのまま参照します。登録を解除しても元フォルダーは削除しません。隠しフォルダーとホーム内を参照するリンクも選択できます。

別のPCのフォルダーは「PCのフォルダーをアップロード」から選択します。この操作ではサブフォルダーを保持してコピーするため、最大2,000ファイル・合計500 MBの転送上限があり、隠しファイルは対象外です。過去にコピーしたサーバーフォルダーの更新機能も維持しています。
