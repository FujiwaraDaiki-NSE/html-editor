Claude Code接続の実装概要

更新: 以下は直接編集に対応した初期実装の記録です。現在はClaudeが指示・レビューを担当し、編集をCodexへ委任します。実行中の追加指示にも対応しています。現在の構成はオーケストレーションの実装概要を参照してください。

モデル選択にClaude Codeを追加し、Codex app-serverを経由せずに既存ログインでHTMLスライドを編集する。

実行経路と責務

対象責務
app/page.tsx明示的なモデル選択、接続先別の送信可否、実行中の停止、対応しない会話操作の無効化。
server/agent-service.mjsモデルと会話IDに対応する実行先へ振り分ける。Claudeの依頼をCodexへ転送しない。接続状態とモデル一覧を統合する。
server/claude/service.mjsclaude -pを起動し、NDJSONの本文・ツール結果・最終結果を共通のeditorイベントへ変換する。ネイティブセッションIDとeditor用履歴を保持する。
server/local-api.mjs接続先共通で実行前スナップショット、プレビュー、編集範囲の検証、同時編集のマージ、復旧を行う。/api/agent/を提供し、既存の/api/codex/も維持する。

バージョンを指定したモデル選択

Opus 5.5などのバージョン名をメニューに表示し、正式ID（例: claude-opus-5-5）を--modelへそのまま渡す。会話履歴にも同じIDを保存し、再開時に保持する。従来のエイリアスは「最新版」と明示する。バージョン指定時は起動イベントのモデルIDを照合し、CLIが異なるモデルを選んだ場合は失敗として扱う。fallbackModelを空配列、switchModelsOnFlagをfalseとして、CLIのモデル切り替えを無効にする。モデル一覧は2026年11月18日の公式カタログで確認した固定リストであり、アカウントの利用権限は実行時に判定される。

認証と操作範囲

Claude Codeのログインをそのまま利用する。資格情報の読み取り・複製やAPIキー入力は追加しない。Read / Edit / Write / Glob / Grepをrestrictedモードで利用し、シェル実行とMCP接続は提供しない。共通editorスキルは実行時の追加指示へ渡す。

状態と履歴

起動受付と完了を分け、正常終了コード・success結果・権限拒否がないことを確認してから完了にする。停止時はプロセスグループへSIGTERMを送り、終了しなければSIGKILLを送る。プロセス終了前に完了を通知しない。異常終了、結果の欠落、JSON破損、権限拒否、履歴保存失敗は失敗として扱う。

会話はプロジェクト別に保存し、履歴からの再開は正確なClaudeセッションIDで行う。再起動時に結果が記録されていない依頼は失敗と表示し、自動で再送しない。内部コンテキストはClaudeへ渡す一方、ユーザーのメッセージ表示は入力本文だけを保持する。

提供する操作と制限

新規会話、会話再開、一覧・検索、名前変更、アーカイブ、editor履歴削除、モデル選択、実行停止に対応する。editor履歴の削除はClaude Code側のセッションを消去しない。実行中の追加指示、会話分岐、内部ゴール、手動圧縮は未対応。既存Codex側の操作は維持する。

確認

実Claude Code 2.1.322で一時HTMLの編集を確認。editor画面からClaude Sonnetを選択し、スライドの見出し変更と変更レビューへの反映を確認。自動テストではストリーミング重複防止、セッション再開、停止、権限拒否、異常終了、プロジェクトの履歴分離、Codex未接続時の実行を検証する。
