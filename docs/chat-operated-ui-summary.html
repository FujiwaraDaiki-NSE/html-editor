Weave · 2026年10月8日

チャットを起点に、画面を見ながら操作する

サイドバーを常設し、エージェントがプロジェクト管理や表示変更などの既存UIを操作できるようにする。操作対象の強調表示により、ユーザーが操作する場所を学べる。

責務

場所役割
Codexの動的ツール画面の読み取り、クリック、入力、選択、キー操作を要求する。
メインチャット読み取り専用の会話がUI操作を調整する。プロジェクトを切り替えても会話の履歴を引き継ぎ、画面操作だけの依頼では編集ロックや復旧スナップショットを作成しない。
スライド編集weave_ui.edit_slidesが既存の編集処理へ委譲する。選択範囲・実行方式・スキル変更権限を守り、編集結果の検証と復旧処理を終えてからメインチャットへ返す。内部の編集スレッドはタスク一覧に表示しない。
ローカルAPI会話とブラウザーセッションを関連付け、要求と応答を照合する。切断・期限切れ・重複応答を扱う。
ブラウザー現在の画面から対象と利用可能な操作を取得し、対象を強調表示してから既存のUIイベントを実行する。
既存の保存・プロジェクトAPI変更の受け付け、整合性の検証、保存結果を決定する。

操作の流れ

  1. エージェントが現在の画面にある操作対象を読み取る。
  2. 対象を指定して操作を要求する。
  3. ブラウザーが対象を再確認し、位置と操作名を表示する。
  4. 既存のボタン・入力欄の操作を実行し、画面の状態を返す。
  5. エージェントが結果を読み、必要な次の操作へ進む。

クリックイベントの送出と、保存やプロジェクト切り替えの完了は別の事実として扱う。対象が存在しない、複数に一致する、無効になったなどの場合は操作を拒否する。

UIと操作対象

チャット以外のタブを選んでもサイドバー領域を維持する。画面内の入力・確認ダイアログは人間とエージェントが共用する。パスワード、ファイル選択、エージェント自身の承認や送信などの制御は画面操作ツールの対象にしない。

任意のJavaScriptやCSSセレクターを受け取って実行する仕組みは設けない。ブラウザーが返す対象情報を使って操作する。

確認方法

npm run lint、npm run typecheck、npm testで静的検査・ビルド・自動テストを行う。GUIではサイドバーの維持、チャットからの操作、対象の強調表示、プロジェクト管理、狭い画面の表示を確認する。

開発環境はNext.js互換の既存vinext起動経路を使用する。このリポジトリにはCompose設定はなく、Web・ローカルAPI・Codex app-serverをnpm run devで起動する。

検証結果

2026年10月8日、プロダクションビルド・295件の自動テスト・型検査・ESLintを通過。実際のCodexとChromeを使い、新規プロジェクト作成と切り替え、選択スライドの編集、分割表示、名前付きマイルストーンの保存を確認した。集中表示と390×844の画面でもサイドバーが残ることを確認した。

中断したターンの遅延操作、複数タブの所有権、期限切れ再接続、内部編集会話の表示混入、親チャットでの編集承認は回帰テストで検証する。内部編集の承認要求には表示先の親会話IDを付け、実際の応答先となる要求IDと子会話IDは変更しない。
