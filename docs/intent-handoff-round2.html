Weave · Concept Extension · Round 2 · 2026-08-11

まだ無い形の次は、もう有る形の温度を渡す。

ラフは「まだ存在しない形」を、位置と大きさのまま渡した。第1巡は「すでに手で直した形」を渡す案を並べた。残っているのは、いま画面にある要素の一つひとつについて、人間の頭の中だけにある決まり具合である。

本命は「決まり具合を成果物の上に置く」。 人間の中には常に「ここは決定」「ここは仮」の地図がある。Weaveは今、全要素を等価に扱っているため、その地図は毎ターン、チャットの「ロゴはそのままで」という一文へ書き直されている。
残った穴 本命の形 渡すもの／渡さないもの 併走候補 追加の原則 実装順

01 · Gap

第1巡の入力マップに、割り当てられなかった行が1つある

第1巡の資料は、失われている思考を7行に整理し、候補を6件出した。表と候補を突き合わせると、6件のどれにも対応していない行が1行だけ残る。

人間の思考今の入力第1巡での扱い
どこに何を置きたいかラフの矩形＋ラベル実装済み
どの要素の話か@ で指差す実装済み
正確にどう見せたいか直接編集・インスペクタ候補01 お手本として渡す
どの案が近いか複数提案を切り替える候補02 良いところを摘む
ここだけは崩したくない毎回チャットで説明未割り当て
自分でもまだ決めきれない曖昧なプロンプト候補03 Agentから問い返す
この参考の、ここが好き画像＋文章で説明候補05 参照レンズ

この行が残ったのは偶然ではない。候補01〜06はいずれも「これから変えたいもの」を渡す機能で、「変えないでほしいもの」を渡す機能が1つも無かった。ところが実際の制作では、確定した部分のほうが先に増えていく。表紙のロゴ、承認済みの数字、社名の表記。作業が進むほど、人間はチャットに保護のための一文を足し続けることになる。

そして「まだ決めきれない」の裏返しも同じ場所にある。仮置きのダミー文は、見た目の上では確定した本文と区別がつかない。Agentから見ると、削っていい文と触ってはいけない文が同じ重みで並んでいる。失われているのは要素そのものではなく、要素に対する人間の確信の強さである。

02 · First feature

決まり具合マーク — Firm / Draft

要素を選んで1キー。状態は3つだが、印が付くのは2つだけで、無印が既定＝今までと完全に同じ挙動である。新しい義務は誰にも発生しない。

FIRM 決まっている

承認済みの数字、確定した見出し、ロゴ。Agentは指示が明示的にそこを指さない限り、文言・サイズ・位置を保つ。

— (既定) 自由

無印。印を付けたことがないプロジェクトは、今日のWeaveとバイト単位で同じ状態のまま動く。

DRAFT 仮置き

置いてあるだけのダミー、後で差し替える写真、まだ言葉になっていない一文。Agentは優先的に埋め、何を仮定したかを述べる。

Example · 4 actions

「ロゴと数字はそのままで」を、二度と書かなくてよくなる。

印を付ける承認済みの数字カードと表紙ロゴを選び、Firm。差し替え前提の写真枠は Draft。
普通に頼む「もっと落ち着いた見た目に」とだけ書く。保護のための一文は要らない。
Agentが読むFirmのidは保ち、Draftのidは自分の判断で埋める。envelopeの2行が根拠になる。
印が残る印は保存され、翌日のターンにも、案のブランチにも同じ地図が付いてくる。

ラフとの対称性。 ラフモードは「まだ無い場所」に矩形を置く。決まり具合マークは「もう有る要素」に温度を置く。注釈レイヤーが決めた2つの入口——空間をドラッグする（D10）と、既存要素を指す（D9）——のうち、後者の語彙をそのまま延ばしたものにあたる。新しいモードは要らない。

承認ゲートではない。 Firmは、人間の直接編集もAgentの書き込みもシステム的には止めない。止めると concept.md 2.1 の「承認ゲートを設けず無条件上書き、undoはgitで一元化」が崩れ、保存経路が二重になる。マークが変えるのはAgentの判断材料だけであり、外れたときの復旧はこれまでどおり履歴が担う。禁止ではなく意図を渡す、というのがラフ以来の一貫した姿勢でもある。

03 · Handoff

Agentへ渡すもの、渡さないもの

追加は shared/context.mjs の editorEnvelope に1キー、contextPromptRules に2文。既存の selected / annotations / overflowing と同じ層に並ぶ。 

{
  "slide": "s2",
  "selected": { "id": "heading-a1", "kind": "h1", "text": "..." },
  "marks": {
    "firm":  ["logo-x7", "metrics-c3"],
    "draft": ["image-b2"]
  }
}

// contextPromptRules への追記
marks.firm lists data-weave-ids the human considers settled:
  preserve their text, size, and position unless the instruction names them.
marks.draft lists ids the human left provisional:
  prefer filling or replacing them, and state what you assumed.

渡すもの

  • Firm / Draft を付けた要素の data-weave-id の並び
  • そのスライドの範囲に限った印（デッキ全体の一覧は送らない）
  • 印の意味を説明する2文のルール
  • 任意のチャット文。空でも成立する

渡さないもの

  • 「変更禁止」という強制。Agentは指示があれば触ってよい
  • 印を付けた理由の入力欄。理由を要求した瞬間にフォームが増える
  • 印の変更履歴。今の地図だけを渡す
  • 印から自動生成した永続ルール（候補04「決定の糸」の領分）

印はどこに残るか。 保存HTMLの data-weave-mark="firm" 属性として持つ。ラフ（D3・非永続）と違い、「崩さないでほしい」は複数ターンにまたがる要求なので、セッション限りにすると毎朝付け直しになって価値の大半が消える。属性なのでgit履歴に乗り、案のブランチをまたいでも付いてくる。エクスポート時には data-weave-id と同じ経路で落とすので、成果物の見た目にも出力にも影響しない。印を付けた要素にだけ属性が書かれるため、diffも汚れない。

成功条件。 チャット入力から「〜はそのままで」「〜は触らないで」という保護の一文が消えること。副次的に、Firmを付けた要素がAgentのターンで書き換わった回数が測れるようになり、これはAgentの指示追従性そのものの指標になる。減らなければ、印は純粋な手間である（第1巡の原則06）。

04 · Candidates

併走候補

第1巡の6件と重複しない、第2巡で新たに立てた候補。いずれも既存の仕組みの上に乗る。

07

行き止まりの記憶 — 戻したことを、そのターンだけ伝える

Zero gesture

人間がAgentの出力をundoした、案を却下した。これは「違う」という最も強い信号なのに、今は完全に捨てられていて、Agentは次のターンで同じ方向を再提案する。直前のターンが取り消されたときだけ、その差分の要約を1件、次のenvelopeに載せる。

拾う思考

言葉にする価値も感じないほど即座の拒否。「これじゃない」と手が動いた事実そのもの。

重要な制約

永続化しない。1件だけ。画面にチップとして見せ、外せる。操作ミスのundoを恒久的な学習にしない。

08

重ねて比べる — 差そのものを知覚できるようにする

Variation

複数提案の閲覧はタブ切り替え＝逐次比較で、人間は細部の差を知覚できない。ラフの重ね照合（R11）と同じ機構を案どうしへ向け、2案を半透明で重ねる。ずれている場所が視覚的に浮かび、その場所を指して選べる。

拾う思考

比較して初めて生まれる好み。候補02「良いところを摘む」は、この知覚が先に無いと成立しない。

既存資産

案ブランチとタブ切替、recallレイヤーの重ね描画。新しいデータ形式をほとんど必要としない。

09

関係を引く — 要素と要素の間にあるもの

Reserved · D11

「この3つはこの順に流れる」「この枠はこの見出しの補足」は、矩形とラベルの組では言えない。注釈レイヤー設計 D11 が形を予約済みで、座標の線ではなく2つの注釈を結ぶ辺として持つ。要素→矩形（この見出しを、右のこの枠へ）が最も効く。

拾う思考

プロジェクト思想が明示している「物事の関係性」。単体の位置と大きさでは表現できない層。

着手時期

設計書の判断に従い、ラフの往復回数の測定より後。矩形だけで減らないなら、辺を足しても減らない。

05 · Guardrails

第1巡の6原則に足す3つ

07

既定を動かさない

何も印を付けなければ、挙動は今日とまったく同じ。新しい入力チャネルは、使わない人に義務を作ってはいけない。

08

禁止ではなく意図を渡す

システムが変更を止めた瞬間、承認ゲートが復活し、undoの一元性（2.1）が崩れる。印はAgentの判断材料に留める。

09

印は出力に残らない

編集のための情報は、成果物の見た目とエクスポートに出ない。data-weave-id がすでに通っている道をそのまま使う。

06 · Sequence

推奨する実装順

PHASE 1

決まり具合を渡す

Firm / Draft。envelopeに1キー、プロンプトに2文、属性1つ。第1巡の候補01より小さく、候補01の暴発も抑える。

PHASE 2

実演を渡す

第1巡の本命「お手本として渡す」。Firmが先にあると、展開してよい範囲がAgent側で自然に絞られる。

PHASE 3

比較を渡す

重ねて比べる → 良いところを摘む。差の知覚を作ってから、部分選択を載せる。

PHASE 4

面を共有する

Agentからの問い返し、決定の糸、関係を引く。指示面を共同思考の面へ変える段階。

判断。 Phase 1 を先に置くのは、それが最も小さいからではなく、他のどの機能よりも早く効果が測れるから。保護の一文がチャットから消えたかどうかは、追加の計測機構なしにログを読めば分かる。

根拠: 思考をAgentへ渡す、次の機能（第1巡）、concept.md 1 / 2.1 / 2.5、docs/annotation-layer-design.md D3 / D9 / D10 / D11、shared/context.mjs の editorEnvelope と contextPromptRules。これは機能提案であり、データ形式とAPIの確定仕様ではない。
