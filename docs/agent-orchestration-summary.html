オーケストレーションの実装概要

更新：着手前の人間承認は、後続の1案編集と3案比較で置き換えた。現在の実行モードは「編集をまかせる」「3案から選ぶ」。以下は導入時の記録。

編集の実行中に追加指示を送れない問題を解消し、選択したCodex／Claudeが担当への指示とレビューを行う。実装担当には別のCodex会話を使う。モデルメニューがオーケストレータの選択を兼ね、実装モデルは明示的に別途選ぶ。

人間の指示 → オーケストレータ → 必要に応じて人間の承認 → Codex担当 → 差分レビュー → 変更範囲・同時編集の検証 → 反映

反映と追加指示の順序

人間の新しい指示は担当のバージョンを更新する。判断前の待機作業は開始せず、古いバージョンのレビューは拒否する。変更前後を閲覧したオーケストレータだけがレビューでき、反映時にもプロジェクトロック内で再確認する。人間の同時編集は従来のマージ処理で保全する。プレビュー表示と反映済み状態を分ける。

接続と復旧

Claudeの会話はローカルAPIからClaude Codeへ直接実行し、Codex app-serverを通らない。スライドの実装担当だけがCodex app-serverを使う。CLIの直接編集権限はClaudeに渡さず、人間の承認操作はAgent UIから除外する。再起動時に未完了作業を再実行・再送しない。状態はGit管理対象外の.weave/orchestration.jsonに保存し、ブラウザー認証トークンは保存しない。

既存機能と制約

変更範囲、同時編集、復旧、名前付き保存、別方向のブランチ、スキル参照とレビュー後の学習を維持する。担当の書き込みは順次実行し、その間も会話を続けられる。進行中の担当がある会話のアーカイブ・削除は、担当の明示的な停止を先に求める。モデル未選択やバージョン不一致を別モデルで代替しない。

確認内容

専用workspaceでClaude Opus 5.5をオーケストレータ、GPT-6.1-Solを実装担当として、人間承認、実装中の追加指示、レビュー、見出しだけの反映を確認した。Codexをオーケストレータに選んだ場合も、別のCodex担当による編集とレビュー後の反映を確認した。自動テストでは重複受付、古いレビュー、停止、再起動、キューの順序、追加指示、閲覧ページの完全性、既存会話の移行を検証する。
