Weave · Concept Extension · 2026-08-11

説明させるのではなく、していることから受け取る。

ラフは、位置・大きさ・対象を言葉へ変換せずAgentへ渡した。次は、ユーザーが形を見ながら行う「直す」「選ぶ」「残す」「迷う」も、そのままAgentへの入力にする。

最優先の提案は「お手本として渡す」。 ユーザーが1か所を直接直した行為を、Agentが他の箇所へ展開できる機能である。Weaveにすでにある直接編集・要素選択・履歴をつなぐだけで、最も日常的な思考を新しい入力へ変えられる。

01 · Input map

Weaveは「何を作るか」を受け取れる。次は「なぜそれが良いか」を受け取る。

現在の機能は、意図を外へ出す入口としてすでに強い。一方で、ユーザーが結果を見て初めて分かる好みは、まだチャットへ言い直さないとAgentへ残らない。

人間の思考今の入力状態次に必要なもの
どこに何を置きたいかラフの矩形＋ラベル拾えている—
どの要素の話か@ で指差す拾えている—
正確にどう見せたいか直接編集・インスペクタ形にはなるその直し方を他へ伝える
どの案が近いか複数提案を切り替える案単位では拾える案の中の良い部分を摘み取る
ここだけは崩したくない毎回チャットで説明失われる成果物上のアンカー
自分でもまだ決めきれない曖昧なプロンプト言語化を要求するAgentから局所的に問い返す面
この参考の、ここが好き画像＋文章で説明部分の意味が落ちる参照の一部分と対象を結ぶ
FEEL違和感や好みを感じる。まだ文章にはならない。
ACT直す、指す、選ぶ、残す。自然な操作として外に出る。
CAPTUREWeaveが操作の差分と対象を構造化する。
HAND OFFAgentはファイルと最小限の文脈から意図を読む。
REFLECT形になった結果を見て、意図そのものが更新される。
02 · Candidates

次の機能候補

優先順位は、変換損失の大きさ、既存機能との接続、ユーザーに新しい作法を要求しないことの3点で付けた。

01

お手本として渡す — この直し方を広げる

最優先

ユーザーが1つの見出しやカードを直接直した後、「この直し方を広げる」を押す。Agentは変更前後と周辺構造を読み、同じ意味の改善を類似箇所やデッキ全体へ展開する。

拾う思考

「言えないが、こうなら良い」という実演。数値やCSSではなく、変更前後の差に宿る判断。

既存資産

直接編集、data-weave-id、Undo履歴、HTML差分、Agentコンテキスト。

02

良いところを摘む — 複数案を部分で選ぶ

Variation+

A案では見出し、B案では数字帯を選んで「残す」。摘んだ部分を小さなトレイに並べ、「これらを使ってまとめる」で新しい案を作る。案を丸ごと採用する二択から、比較しながら意図を発見する体験へ進める。

拾う思考

「全体は違うが、ここは好き」という部分的な選好。ユーザー自身も比較して初めて気づく好み。

既存資産

提案ブランチ、タブ切替、選択要素、コミット参照。摘んだ要素はブランチ＋commit＋idで特定できる。

03

Agentも指示面に書く — 迷いをその場所へ返す

Bidirectional

Agentが不明点を長いチャットで聞く代わりに、キャンバス上の対象へ「ここはA/Bどちらか」「この余白は意図的か」を置く。ユーザーは選択、ラフの描き直し、直接編集のいずれかで答える。

拾う思考

未確定、保留、局所的な迷い。曖昧さを消してから作業するのではなく、形の上で解消する。

既存資産

注釈レイヤーの「指示面」と送信済み注釈の重ね表示。発信者と回答状態を足せば概念がつながる。

04

決定の糸 — 採否からデッキの約束を残す

Memory

案を採用・却下したとき、Agentが差分から「数字を主役にする」「説明文は2行以内」のような判断候補を1つだけ返す。ユーザーがピン留めしたものだけが、以後の生成に常駐する。

拾う思考

繰り返し現れる好みと制約。毎ターン同じことを言い直す負担をなくす。

重要な制約

Agentが勝手に「好み」を確定しない。履歴は証拠、ピン留めだけが約束。いつでも成果物から辿って外せる。

05

参照レンズ — 画像の一部分を借りる

Reference

参考画像を貼り、好きな部分だけを矩形で囲み、スライド上の対象へつなぐ。「この画像に似せる」ではなく、「この部分を、ここを考える材料にする」という関係を渡す。

拾う思考

余白感、密度、写真の扱いなど、名前を知らなくても見分けられる視覚的な好み。

重要な制約

参照画像を真似る座標指定にしない。切り抜きは根拠であり、Agentが表現方法を選べる余白を残す。

06

ストーリーの束 — スライドを意味で束ねる

Deck level

フィルムストリップ上でスライドを囲んで束にし、「問題」「転換」「証拠」など短い役割だけを置く。Agentは個々のスライドではなく、話の流れと重複・欠落を直す。

拾う思考

順番だけでは表せない、まとまり・伏線・強弱。キャンバスのラフをデッキ全体の構造へ広げる。

既存資産

アウトライン、フィルムストリップ、並べ替え、複数スライドのAgent編集。

03 · First feature

最初に作るなら「お手本として渡す」

ラフが「まだ存在しない形」を渡す機能なら、これは「すでに手で直した形」を渡す機能である。0→1と手直しの両方を、ユーザーに新しい作法を覚えさせずに補完できる。

Example · 4 actions

数字カードを1つ直しただけで、デッキ全体が学ぶ。

直接直すユーザーが数字を大きくし、ラベルを短くし、余白を詰める。
お手本にする直したカードを選び、「この直し方を広げる」を押す。
範囲を選ぶ現在のスライド／似た要素／デッキ全体の3択だけを出す。
Agentが展開同じpx値の複製ではなく、「数字を主役にする」という意味を類似箇所へ適用する。

Agentへ渡すもの

  • お手本要素の data-weave-id
  • 変更前と変更後のHTML、および最小の周辺構造
  • 変更されたCSSプロパティとテキストの差分
  • 適用範囲: slide / similar / deck
  • 任意のチャット文。空でも実行できる

渡さないもの

  • 「font-sizeを32pxにせよ」という機械的な再現命令
  • デッキ全体の重複HTML
  • ユーザーが触っていない編集履歴
  • 自動生成された永続ルール
  • お手本と無関係な未保存差分
成功条件: 同じ修正を3か所以上で繰り返していた場面で、手動修正1回＋Agent 1ターンに減ること。Agentの結果が外れた場合も、お手本と結果を重ねて差を指せること。
04 · Guardrails

すべての候補に共通する設計原則

01

行為が先、言葉は任意

入力フォームを増やさない。直す、選ぶ、囲むという自然な行為から文脈を作り、言葉は不足を補うためだけに使う。

02

近似を、文字どおり再現しない

ラフの座標と同じく、実演や参照は意味を読む材料。Agentはフロー構造とデッキ全体の整合を優先する。

03

真実へ混ぜすぎない

一時的な比較・問い・お手本は下書き。採用された成果物はHTML、明示的にピン留めした約束だけを永続化する。

04

対象と根拠を一緒に渡す

idだけでは「何を」、差分だけでは「どこへ」が欠ける。対象、前後、周辺、範囲を最小の塊として渡す。

05

Agentの迷いも画面へ戻す

人間だけに明確化の責任を持たせない。Agentが判断できない箇所も、成果物と同じ場所で共同編集できるようにする。

06

往復回数で評価する

機能の利用数ではなく、意図した状態までの往復が減ったかで測る。減らなければ、その入力は純粋な手間である。

05 · Sequence

推奨する実装順

PHASE 1

実演を入力にする

「お手本として渡す」。まず1要素・現在のスライドから始め、差分の意味をAgentが正しく展開できるか測る。

PHASE 2

比較を入力にする

「良いところを摘む」。複数提案の採否を案単位から部分単位へ進め、選択の理由を言葉なしで運ぶ。

PHASE 3

指示面を共有する

Agentからの問い返しと、明示的に残す「決定の糸」。一方向の指示面を、共同思考の面へ変える。

判断: 参照画像とストーリー構造は価値があるが、新しいデータとUIを多く必要とする。先に「実演」と「比較」で、非言語入力が本当に往復を減らすことを確認してから広げる。
